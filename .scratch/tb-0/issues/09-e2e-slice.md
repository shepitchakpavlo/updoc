# 09 — E2E slice

**What to build:** перший наскрізний прогін TB-0: API-скрипт проходить весь ланцюжок (заявка → лінк → upload → мок-assessment → policy → Drive), SPA-форма — один ручний прохід; перевірка DoD-гейта і фіксація результату для переходу в Phase 1.

**Blocked by:** 08, 05

**Status:** ready-for-human

- [x] API-скрипт проходить увесь ланцюжок локально (артефакт + in-process-верифікація; живий прогін — оркестратор)
- [x] Ручний SPA-прохід: прийнятий файл з'являється в тестовій папці Drive; відхилений — ніколи, з поясненням (артефакти: `--spa` + зразки; сам прохід — людина)
- [x] Повторний запис після технічного збою не створює дублікатів (крок retry у сценарії + тести 08)
- [x] Тестові файли (2–3 приклади) — поза репо
- [ ] DoD TB-0 підтверджено → гейт у Phase 1; план Phase 1 підтверджено (оркестратор/користувач)
- [ ] Оновлення статусу фази в нотатках Obsidian — лише після узгодження з користувачем

## Answer

Реалізовано (apps/api; web не змінювався — ручний SPA-прохід іде за готовою формою тикета 05).

**Наскрізний прогін — `npm run e2e -w @updoc/api`** (`apps/api/scripts/e2e.ts` + `scripts/e2e/slice.ts`):
- Весь ланцюжок через публічні ендпоінти: POST /applications → лінк → токен з лінка → GET /applications/access → GET /applications/submissions → POST /applications/upload (multipart) → мок-assessment → policy → FinalDestination. Результат перевіряється тим самим сервісним акаунтом (той самий обмежений доступ drive.file, що в API): папка заявки знайдена, файли, імена, MD5, id.
- Кроки: зразки → прибирання старої папки попереднього прогону → заявка+токен → папка в тестовому Drive → доступ за токеном (компанія/ПІБ/чекліст) → порожній список слотів → відхилений зразок (маркер іншого слота; feedback policy) → замалий файл (feedback провайдера) → у папці 0 файлів → прийнятий PNG → прийнятий PDF → рівно 2 файли з MD5 зразків → retry того самого файла — той самий id, без дубліката → фінальний стан слотів через API; наприкінці папка заявки прибирається (бест-еффорт, не засмічує тестовий Drive).
- **Ідемпотентність (DoD-3):** крок retry — повторний upload тих самих байтів (погляд клієнта після технічного збою) перевикористовує id файла: 3 upload-и → 2 createFile. Збій ledger на рівні сервісу вже покритий тестами тикета 08 (реальний FinalDestination над in-memory Drive).
- **`--spa`:** заявка + лінк + зразки; папка лишається для ручного проходу; друкується порядок дій (спершу відхилений зразок — пояснення і порожня папка, потім прийняті — з'являються в папці).
- PII-безпека: токен — лише в заголовку x-access-token (не в URL/логах API); сценарій не логує лінк/токен (крім навмисного друку лінка у `--spa` для оператора); зразки синтетичні.

**Тестові файли поза репо** (`scripts/e2e/samples.ts`): 3 синтетичні зразки без PII генеруються в `os.tmpdir()/updoc-e2e-samples` (дефолт), ніколи не комітяться. Прийняті PNG/PDF несуть маркер мока `mock:slot=` (той самий контракт, що в assessment/mock.ts) і ≥4KB; PDF лишається валідним після вбудовування маркера (pdf-lib рахує сторінки). Відхилений зразок — маркер іншого слота (policy відхиляє з поясненням). `ensureSamples` ідемпотентний — не перезаписує наявні файли (ручний прохід і повторні прогони безпечні).

**TDD (red-green, дві seams):** `test/e2e-samples.test.ts` (зразки проти реальних preflight + мок-assessment + policy) і `test/e2e-slice.test.ts` (весь ланцюжок in-process: реальні сервіси + фейк-репозиторії + фейк-Drive; fetch-адаптер над Fastify inject — той самий multipart-розбір і маршрути, що в живому прогоні). 11 нових тестів.

**Верифікація:** `make typecheck`, `make test` (119 API + 17 web), `make build` — чисті; CLI: `--help` → 0, `--spa` без API → 1. Селф-рев'ю за skills (code-review: Standards/Spec паралельними сабагентами): Spec — знахідок немає; Standards — виправлено: exit-code `--spa` при збої (був 0 → тепер 1), дублікат формату імені папки (винесено `applicationFolderName` у сервіс — єдине джерело правди), назва helper-а `require` → `check`, HELP (додано `--samples-dir`, виправлено посилання на .env.example). Тріаж: дублікати regex `/a/{token}` і multipart-білдера — свідома конвенція монорепо без спільного пакета типів (web/src/api.ts); folderId-guard — вимагає `noUncheckedIndexedAccess`.

**Залишається оркестратору/людині** (агент не стартував сервіси):
1. Живий прогін: `make dev` + секрети Drive в `.env` → `npm run e2e -w @updoc/api` (очікується «=== НАСКРІЗНИЙ ПРОГІН TB-0: УСПІХ ===», exit 0).
2. Ручний SPA-прохід: `npm run e2e -w @updoc/api -- --spa` → лінк і зразки → відхилений зразок спершу (пояснення у формі; файла немає в папці), потім прийняті (з'являються в папці «Працівник E2E — ТОВ E2E» тестового Drive).
3. DoD-гейт → Phase 1: підтвердження плану Phase 1 і оновлення статусу фази в нотатках Obsidian — лише після узгодження з користувачем (критерії 5–6; нотатки не чіпалися).
