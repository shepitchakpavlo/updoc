## Answer

Реалізовано (apps/api + apps/web):

- `GET /applications/submissions` — новий ендпоінт стану для форми: за токеном у `x-access-token` → `{ submissions: [{ slot, status, feedback }] }` у порядку чекліста; невідомий/відсутній токен → 404. `feedback` — причина assessment для `needs_reupload` (причини policy з'являться в assessment тикетами 06/07 і покажуться без змін SPA).
- SPA (React + Vite): лінк `/a/{token}` → токен із шляху, дані заявки (`GET /applications/access`) і стан слотів (`GET /applications/submissions`) — `Promise.all`, форма: ПІБ, компанія, чекліст зі слотів 1–2, 11–12, 13–14, 15–16. Кожен слот — `SlotCard`: мітка, бейдж стану (очікується / перевіряється / прийнято / потрібно перезавантажити), один файловий інпут (JPG/PNG/HEIC/PDF), фідбек. Upload — multipart через `POST /applications/upload`; стан оновлюється одразу з відповіді API, повторний вибір файла замінює (upsert на API, `input.value` скидається, щоб той самий файл можна було обрати знову). Помилки upload (413/400/404) — фідбек слота з message API; невідомий токен/збій завантаження форми — окремі повідомлення.
- Типовий клієнт `src/api.ts` (`createApi`, fetch інжектується для тестів), мітки станів `src/status.ts`. Vite dev-proxy `/applications` → `:3000` (у проді SPA сервиться тим самим origin).
- Контракт для тикета 09 (e2e-зріз): SPA можна прогнати вручну через `make dev` → лінк заявки → завантажити файл у слот → стан і фідбек видно одразу; після 06/07 стан оновлюватиметься через `GET /applications/submissions`.

Верифікація: 59 API-тестів (node:test + tsx, seam-и: fake repo/service) + 16 web-тестів (vitest + jsdom + @testing-library/react, seam-и: fake fetch / fake api), `make typecheck` і `make build` чисті. Додано devDependencies у `@updoc/web`: `vitest`, `jsdom`, `@testing-library/react`. Ручний прохід SPA — тикет 09 (оркестратор); довготривалі сервіси тут не запускалися.
